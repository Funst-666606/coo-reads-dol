# 发布流程

每次要更新 GitHub 时，按下面顺序做，缺一项不发版。

## 1. 改代码前

- 确认改的是 `main`（完整版）还是 `sfw`（学习版）；
- 两边共用的文件（协议、模组 `main.ts`/`ui.ts`/`pages.ts`、`boot.json`）改完后要同步到另一分支。

## 2. 改完后

```bash
node node_modules/typescript/bin/tsc -p tsconfig.json --noEmit
node scripts/test.mjs
node scripts/gen-describe.mjs     # 改了工具/事件/提示词时
node scripts/build-all.mjs
node scripts/package-release.mjs  # 完整版产物
node .cache/pack-sfw.mjs          # 学习版产物（在 sfw 分支）
```

## 3. 更新日志（必须）

三处都要写，内容一致但面向对象不同：

| 文件 | 内容 |
|---|---|
| `CHANGELOG.md`（根） | 面向用户：这次 Release 改了什么、现象/根因/修法 |
| `packages/cortico-world-dol/CHANGELOG.md` | World 侧的版本条目 |
| `packages/dol-mod/CHANGELOG.md` | 模组侧的版本条目 |

条目格式：

```markdown
## 0.1.x - YYYY-MM-DD

- 修复：<现象>。根因是 <原因>；现在 <修法>。
- 新增：<功能>，入口在 <位置>，限制是 <限制>。
- 变更：<行为变化>，旧行为是 <旧>，新行为是 <新>。
```

禁止只写“优化体验”“修复若干问题”。

## 4. 版本号

- 修 bug：patch +1；
- 加功能：minor +1；
- 破坏性改动：major +1；
- World、模组、学习版各自独立升版，不要混用。

## 5. GitHub Release

- 标题：`欲都孤鱼与多邻鱼 <World 版本> / 模组 <模组版本>`
- 正文必须包含：
  - 本次版本号（World / 学习版 / 模组）；
  - 新增 / 修复 / 变更；
  - 升级方式（只换模组，还是两个都换）；
  - 已知问题；
  - 校验和。
- 附件：World 完整版、学习版、模组、`SHA256SUMS.txt`。

## 6. 发布后

- `npm view` 确认版本；
- 若走 staged，去 npm 的 Staged Packages 批准；
- 需要时开 `[sync]` issue 让 Cortico 市场收录；
- 记录一次 `git log` 与 Release 链接，方便回溯。
