# 欲都孤鱼与多邻鱼 · 技术方案

- 版本：v0.1（草案）
- 日期：2026-10-31
- 关联：[需求规格](需求规格.md)
- 目标环境：Coopanion 0.2.16（Cortico，world api 6）｜ DoL 0.5.12.13 + ModLoader 2.101.1 ｜ Windows

---

## 1. 总体架构

```
┌─────────────────────────────┐        WebSocket (127.0.0.1)        ┌──────────────────────────┐
│  DoL 游戏页面（本地 html）   │  ←──── JSON 消息 ────────────────→  │  Cortico World 扩展       │
│                             │                                     │  cortico-world-dol        │
│  CooBridge.mod.zip          │                                     │  ├─ WS server             │
│  ├─ 场景/选项/状态提取       │                                     │  ├─ 生词镜像 / 统计        │
│  ├─ 单词卡 / 问句卡          │                                     │  ├─ tools（讲解回传等）    │
│  ├─ 生词本 / 复习 / 导出     │                                     │  ├─ events（场景/提问）    │
│  └─ 设置 / 诊断              │                                     │  └─ WebUI 面板             │
└─────────────────────────────┘                                     └───────────┬──────────────┘
                                                                                 │ pushEvent / ToolOutcome
                                                                                 ▼
                                                                    ┌──────────────────────────┐
                                                                    │  Coo（Persona + 模型）    │
                                                                    │  pet_say / pet_ask        │
                                                                    └──────────────────────────┘
```

关键链路：**翻译请求是 Coo 驱动的**。World 不能直接调模型，所以：

```
玩家点句子 → mod 发 sentence(请求 id) → World 推事件 dol.ask(id)
          → Coo 调工具 dol_teach(id, 译文, 讲解) → World 回 reply(id) → mod 显示
```

超时 20 秒；失败可重试；同一句以哈希缓存。

## 2. 组件职责

| 组件 | 职责 | 不负责 |
|---|---|---|
| `dol-mod` | 游戏内一切 UI、DOM 读取、本地词典、生词本、复习、导出、协议客户端 | 调模型、跨游戏持久化 |
| `cortico-world-dol` | 连接管理、消息路由、Coo 的工具与事件、配置、面板、生词镜像 | 渲染游戏内 UI、读游戏 DOM |
| `protocol` | 消息类型、版本号、校验函数（两端共用、零运行时依赖） | 业务逻辑 |

## 3. 协议 v1

传输：WebSocket，文本帧，JSON。首条消息必须是 `hello`，否则断开。心跳 20s，60s 无消息视为断开。

### 3.1 mod → World

| type | 载荷 | 说明 |
|---|---|---|
| `hello` | `protocol`, `client{name,version}`, `game{version,passage,lang}` | 握手；`lang` 非 `en` 时 World 直接回 `error` 并断开 |
| `scene` | `seq`, `passage`, `title?`, `text`, `choices[{index,label}]`, `state{location?,day?,time?}` | 换场景；`text` 截断 4000 字符 |
| `choice` | `index`, `label` | 玩家点了选项（点击时，非跳转后） |
| `sentence` | `id`, `text`, `context?` | 请求翻译/讲解；`id` 由 mod 生成（hash） |
| `word` | `id`, `word`, `sentence` | 本地词典未收录，请求 Coo 补全 |
| `vocab` | `op: add\|remove\|review`, `entry` | 生词镜像 |
| `ping` | — | 心跳 |

### 3.2 World → mod

| type | 载荷 | 说明 |
|---|---|---|
| `hello_ok` | `protocol`, `world{version}`, `features[]` | 握手成功 |
| `reply` | `id`, `kind: sentence\|word`, `ok`, `payload`, `source: local\|coo\|ai` | 请求的应答 |
| `notice` | `level: info\|warn\|error`, `text` | 面板/游戏内提示（如「Coo 未配置模型」） |
| `error` | `code`, `message` | 不可恢复，mod 显示并停止重连 |
| `pong` | — | 心跳 |

### 3.3 错误码

| code | 含义 | mod 行为 |
|---|---|---|
| `bad_hello` | 协议版本或首帧不对 | 断开、显示原因 |
| `i18n_detected` | 游戏是中文 | 通常由 mod 自己先拦；兜底 |
| `coo_unavailable` | Coo 未运行/未接模型 | 卡片显示「Coo 不可用」 |
| `timeout` | 讲解超时 | 显示重试 |

## 4. DoL 模组设计

### 4.0 已对着构建核对过的事实（2026-10-31）

| 假设 | 结论 | 依据 |
|---|---|---|
| 正文容器 | `#passages` 一定存在 | 构建里没有 `StoryInterface` passage，SugarCube 用默认布局；引擎要求 `StoryInterface` 内必须有 `id="passages"` |
| 选项 | `<a class="link-internal" data-passage="…">` | 游戏用 `<<link [[Label|Passage]]>>`；引擎宏生成 `link-internal` + `data-passage` |
| 选项编号 | 是 `(1) ` 形式（`numberPrepend="("`、`numberAppend=") "`） | DoL 的 `Links` 模块默认值；模组读取时剥掉 `(n)` 前缀 |
| 游戏版本 | `window.StartConfig.version = "0.5.12.13"` | 构建内 `const StartConfig = { … version: "0.5.12.13" … }`；没有 `Version` passage |
| 天数 | `$days`（不是 `$day`） | 存档详情 `days: clone($days)`、`$wraith.days = ($days - 60)` |
| 时间 | `$time` 是「当天第几分钟」 | `$minute` 由 `$time - ($hour * 60)` 算出；模组转成 `HH:MM` |
| 地点 | `$location` 字符串 | 多处 `<<set $location to …>>` |
| `State.passage` | 可用 | 游戏代码里有 38 处引用 |

### 4.1 加载阶段（boot.json）

| 字段 | 用途 |
|---|---|
| `scriptFileList_inject_early` | 尽早注册版本/环境探测（只读、同步） |
| `scriptFileList` | 主体：UI、协议、词典、生词本 |
| `styleFileList` | 全部样式，类名前缀 `cb-` |
| `imgFileList` | 图标（SVG/PNG），不引用游戏素材 |

### 4.2 启动顺序

1. 读 `window.modUtils` / `State` 是否存在 → 否则静默退出。
2. **汉化检测**：以下任一命中 → 顶部可关闭横幅 + **完全停用**（不建连接、不注入学习 UI）：
   真正的汉化包名（`modi18n` / `汉化` / `中文补丁`）、`mainLanguage` 非 `en`、当前正文汉字占比 ≥ 8%、页面 `lang` 非 `en`。
   通用插件 `I18nTweeReplacer` 不算汉化。
3. 读游戏版本（`Version` passage / `State.variables.version`），与支持列表比对，仅警告。
4. 初始化本地存储（生词本、缓存、设置），迁移版本号。
5. 挂 DOM 事件：`:passagestart` / `:passageend` / `:passagedisplay`。
6. 连接 WS；失败则指数退避重连。
7. 注入悬浮按钮与面板（默认折叠）。

### 4.3 场景提取

- 正文：`#passages` 内可见文本（排除 UI 区），按段落切分，`innerText` 归一化空白。
- 选项：`#passages a.link-internal`（以及 DoL 自定义的选项容器）→ `{index,label}`。
- 状态：读 `State.variables` 中稳定的字段（`location`、`day`、`time`）；字段名以 spike 实测为准，读不到就省略。
- 同一 passage 的重复渲染用 `(passage, textHash)` 去重。

### 4.4 点词 / 点句

- 用 `document.caretRangeFromPoint`（回退 `caretPositionFromPoint`）取字符位置，**不重写 DOM**。
- 单词：按 `[A-Za-z][A-Za-z'’-]*` 向两侧扩展；连字符词整体取；句末标点不吞。
- 句子：从点击位置向两侧扩到 `. ! ? …` 或段落边界；跨节点时退化为「整段」。
- 高亮：`CSS.highlights`（Chrome 支持），失败则不高亮，绝不插入 `<span>` 包裹正文。
- 弹层：`position: fixed`，按选区矩形定位，翻转避免越界；`Esc` / 点外部关闭。

### 4.5 词典与词根

- 词典：`data/dict.json`（构建期生成，**不进版本库**），结构 `{word: {phonetic, pos, gloss, rank}}`；查不到再试还原形。
- 词形还原：规则表（`-s/-es/-ed/-ing/-er/-est/-ly` + 双写辅音 + 去 e），命中词典才算成功，否则用原词。
- 词根：`data/roots.json`（自建，CC BY-NC-SA 4.0），条目 `{part, type: prefix|root|suffix, meaning, examples[]}`；拆解器按「最长前缀 → 最长后缀 → 词根表命中」生成候选，**命中不足就返回 null（显示无可靠词根）**。
- 未收录：点「问 Coo」→ 协议 `word` → Coo 调 `dol_define` 回传 → 缓存（标注 `source: coo`，徽标「AI 推测」）。

### 4.6 本地存储（localStorage，前缀 `cb.`）

| key | 内容 |
|---|---|
| `cb.vocab.v1` | 生词条目数组 |
| `cb.trans.v1` | 句子哈希 → 译文/讲解（LRU，上限 500 条） |
| `cb.settings.v1` | 模式、字号、开关、端口 |
| `cb.stats.v1` | 每日计数 |

所有读写带 try/catch；配额满时提示导出并降级为内存态。

### 4.7 构建

TypeScript → esbuild（IIFE，target chrome110）→ `dist/coobridge.js` + `dist/coobridge.css` → 打包脚本生成
`CooBridge.mod.zip`（boot.json 在根目录，路径大小写一致）。

## 5. World 设计

### 5.1 定义

```ts
export const DOL: WorldDefinition<DolConfig> = {
  id: 'dol',
  label: '欲都孤鱼与多邻鱼',
  defaults: () => ({ enabled: false, port: 17321, mode: 'trigger', maxCommentsPerDay: 0, sceneTextLimit: 4000 }),
  preflight: ...,
  create: (ctx) => new DolWorld(ctx),
  describe: { tools: describeTools(DOL_TOOL_DECLS, {...}), events: [...] },
}
```

### 5.2 服务

- `http.createServer` + `ws`（Coopanion 已带 `ws`），只监听 `127.0.0.1`，端口被占时 17321–17330 顺延。
- 握手校验：首帧 `hello`、`protocol === 1`、`lang === 'en'`。
- 单客户端：新连接顶替旧连接（避免刷新后双开）。
- 来源校验：允许 `Origin: null`（`file://`）与 `http://127.0.0.1`；拒绝其它 `http(s)` 来源。

### 5.3 工具

| 工具 | 作用 |
|---|---|
| `dol_teach` | 回传某条 `sentence` 请求的翻译与讲解（必须带请求 id） |
| `dol_define` | 回传某条 `word` 请求的释义/词根/同根词 |
| `dol_now` | 当前场景摘要、连接状态、今日统计 |
| `dol_vocab` | 生词查询：列表/统计/到期 |
| `dol_mode` | 读取或切换 主动/触发/被动 |
| `dol_note` | 让 Coo 给某条生词写一句记忆钩子（可选） |

工具只做「读写 World 状态 + 转发给 mod」，不自行生成文本。

### 5.4 事件

| type | 触发 | 默认 trigger |
|---|---|---|
| `dol.scene` | 换场景（主动/触发模式） | `debounce` |
| `dol.choice` | 玩家点选项 | `debounce` |
| `dol.ask` | 玩家点句子，等 Coo 讲解 | `flush` |
| `dol.word_ask` | 本地词典未收录 | `flush` |
| `dol.connected` / `dol.disconnected` | 连接变化 | `piggyback` |

`dol.ask` 的事件正文明确写出请求 id、原句、上下文，要求 Coo 用 `dol_teach` 回答；未回答则超时。

### 5.5 环境提示词（ENV_PROMPT.md）

写清：现在是 DoL 英文原版；三种模式的发言边界；点句请求要优先用 `dol_teach` 回答、翻译要自然、讲解 1–3 条；
不剧透、不替玩家做选择、成人内容中性处理；短评一句话。

### 5.6 面板

连接状态、模式切换、发送范围、今日统计、生词总数、最近 10 条诊断、导出/清空缓存、端口与「复制连接地址」。

### 5.7 数据文件（`ctx.dataDir`）

| 文件 | 内容 |
|---|---|
| `dol-vocab.json` | 生词镜像（只读同步自 mod） |
| `dol-stats.json` | 每日计数 |
| `dol-conn.json` | 最近一次连接的端口与时间（诊断用） |

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Coo 忙/未接模型导致讲解超时 | 核心功能不可用 | 20s 超时 + 重试 + 面板显示原因；后续可加「快速通道」 |
| DOM 结构随游戏更新变化 | 取不到正文/选项 | 多选择器回退；失败降级但仍可查词（选区取词不依赖结构） |
| 点词位置 API 在 Electron/Chrome 差异 | 取词不准 | 双 API 回退 + 选区兜底 |
| 词典许可 | 不能发布/分发 | v0.1 只本地生成；发布前换授权源 |
| 成人内容外发 | 隐私/合规 | 默认只发当前场景、可切被动；中性讲解写进提示词 |
| 端口冲突 | 连不上 | 17321–17330 顺延，面板显示实际端口 |
